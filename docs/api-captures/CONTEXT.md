## Live probe results — what to fix

> **Trust these over the plan's pre-identified fixes.** The live run overturned two of the plan's assumptions.

### CONFIRMED endpoint fixes (Task 3 — `src/api/endpoints.ts`)

| # | Fix | Evidence |
|---|---|---|
| 1 | `expenses.updateExpense`: method `PATCH` → `PUT` | `PUT /expenses/:id → 200` |
| 2 | `billReminders.updateBill`: path `/bills/:id` → `/bills/bills/:id`, method `PUT` → `PATCH` | `/bills/:id → 404`, `/bills/bills/:id → 200` |
| 3 | `auth.updateProfile` is missing — add it as `PATCH /auth/update-profile` | `GET /auth/update-profile → 404` (wrong method confirmed) |
| 4 | Add `categories.getCategoriesByType` as `GET /categories/by-type?type=:type` | `GET /categories/by-type?type=income → 200` (different endpoint, confirmed working) |

### CONFIRMED type fixes (Task 4 — `src/api/types.ts`)

| # | Fix | Evidence |
|---|---|---|
| 1 | `RegisterUserRequest`: add `pin: string` and `preferredReminderHour?: number` | Registration succeeded with these fields |
| 2 | ~~`UpdateOnboardingRequest`: flatten to `{ incomeSource, incomeRange, financialGoals }`~~ — **DO NOT DO THIS**. Server responded `"Step identifier is required."` → the current nested `{ step, data: {...} }` shape may be correct. Inspect the current `OnboardingScreen.tsx` logic and `UpdateOnboardingRequest` in `types.ts` before changing anything here. |
| 3 | `ResetPasswordRequest`: change `{ token, newPassword }` → `{ email: string; otp: string; newPassword: string }` | Postman shows this shape; current type is wrong |
| 4 | ~~`RegisterNotificationTokenRequest`: rename `fcmToken` → `expoPushToken`~~ — **DO NOT DO THIS**. Server responded `"FCM token required"` → the field name is `fcmToken`. Current `types.ts` is already correct. Postman was wrong. |
| 5 | Add `UpdateProfileRequest` interface: `{ firstName?: string; lastName?: string; phoneNumber?: string; preferredReminderHour?: number }` | Needed for the new `auth.updateProfile` endpoint |
| 6 | `UserProfile` type: field is `KycStatus` (capital K) — verify current type matches | Live `GET /auth/profile` returns `KycStatus` |

### Response shape notes (for fixing response types in Task 4)

Inspect `docs/api-captures/zorah-api-responses.json` for full shapes. Key findings:

- `GET /expenses/get-expense` → `{ data: Expense[], month: number, year: number }` — expenses are in `data`
- `POST /expenses/add-expense` → returns the `Expense` object directly (no wrapper)
- `GET /bills` → `{ summary: {...}, bills: Bill[] }` — bills are in `bills`
- `GET /auth/profile` → flat object with `_id`, `firstName`, `lastName`, `email`, `phoneNumber`, `biometricEnabled`, `KycStatus`, `preferredReminderHour`, `authProvider`, `fcmTokens` (array), `createdAt`, `updatedAt`, `__v` (plus redacted `refreshToken` and `pin`)
- `POST /income/add-income → 500` because `category: "salary"` is not a valid enum — check `GET /categories?type=income` in the capture for valid values, then fix the `AddIncomeRequest` type's `category` field to use the correct union type

**Inspect a specific endpoint's live response:**
```bash
node -e "
const f = require('./docs/api-captures/zorah-api-responses.json');
const e = f.endpoints.find(x => x.name === 'get-income');
console.log(JSON.stringify(e?.responseBody, null, 2));
"
```

Replace `'get-income'` with any `name` field from the capture.

**List all successful endpoints:**
```bash
node -e "
const f = require('./docs/api-captures/zorah-api-responses.json');
f.endpoints.filter(e => e.statusCode >= 200 && e.statusCode < 300)
  .forEach(e => console.log(e.method.padEnd(7), e.path));
"
```
